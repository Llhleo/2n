## 最终体验

开头看到的是一个完整的 2ⁿ，结尾理解的是：它由同行的人共同构成。

Core 是公会的集合形态与记忆载体。五境改变它所处的环境，管理层让连接变得清楚，成员让结构获得名字，液滴把个体关系转化为共同力量；半周年影片则把视觉隐喻落到真实记录上。

“贯穿”指身份、空间和状态连续，不要求同一套网格在每个章节都保持可见，也不要求 WebGL 全程持续绘制。阅读管理层时，Core 退到边缘；液滴表现时，让已有系统接管；影片播放时，停止装饰性渲染。

这个方向适合 2n，因为现有网站本来就有从世界到人、再汇聚成整体的故事，并已有 Hero 标识向页眉移动的连续设计。风险在于过度强调雕塑而削弱真实成员，以及把已经顺畅的原生横滑重新变成动画播放器。必须先证明体验收益，不能以使用 Three.js 作为成功标准。

## Core 的视觉语言

主案：**具有层次与连接结构的 2ⁿ**。保留现有大 2、小上标 n 的比例关系，使用手工设计的圆角截面和连续弯曲骨架；侧面显露深度与连接缝，正面优先识别。不是直接调用字体挤出后添加金属材质。

建议先比较两个低成本形态：A 为完整剪影内的分层实体；B 为两条互相连接的带状骨架。优先 A，因为它更容易接回现有品牌与高表面张力的圆润轮廓。B 若显得像普通无限符号或线圈，就淘汰。纯玻璃字、镀铬字和随机漂浮碎片不作为默认方案。

设计约束：

- 轮廓、上标位置与一个固定连接特征共同维持辨识度，不能只靠材质认出它。
- 支持拆成少量结构件；成员阶段再用稳定索引映射到多个节点。五境数量、管理层人数、成员人数不硬编码成同一种结构数量。
- 主要阅读视角保持约正面至左右 45°；更极端视角只作短转场。不要承诺文字在任意 360° 方向仍可读。
- 保留纸白、墨黑、游戏生态色与冷蓝液体的关系。开场先用墨色实体与克制的冷色边缘，后段逐步显露内部冷蓝；不把全站改成统一的玻璃科幻风。
- 五境影响光色、结构的松紧和环境遮挡，避免每境随机换一种模型。材质变化必须仍让人认出同一个主体。
- 先用低面数实体证明轮廓、遮挡和运动成立，最后才考虑复杂材质。

## 一条有因果关系的叙事

| 章节 | Core 与内容的关系 | Camera / 视觉重点 | 原有资产处理 |
| --- | --- | --- | --- |
| Hero | 完整 2ⁿ 从已有五境地貌中显露，建立身份 | 小幅偏航露出厚度，地貌遮住底部；短暂居中 | 保留字标关系、三层地貌、原图、开场文案与跳过入口；重排开场时序 |
| 五境 | 同一主体经过不同环境，连续携带前一境留下的光色 | 相机与地貌共同推进，环境接缝处不把模型重置回中央 | 保留五张图、顺序和文案；重做跨境接缝、遮挡与 Core 路径 |
| 同行的力量 | 第一次展开，让整体露出内部连接 | 只在此做一次明显视点变化，给出结构的可理解全貌 | 保留两段文案；将 bridge-orb 的叙事功能交给 Core，避免同时出现两个无关球体 |
| 管理层 | 结构保持稳定，当前人物的贡献与一处连接呼应 | 主体靠边、降低运动，人物姓名与贡献为主 | 保留数据、顺序与文字入场；调整排版留白与连接位置，不将名字贴到旋转表面 |
| 成员 | 结构上的节点逐渐对应真实名字 | 从整体到个体，保持同一中心与色彩 | 保留 95 人名单和成员路径；新增节点到姓名的稳定映射 |
| 汇聚与液态 | 节点转为已有小液滴，再接触、连颈、吸收 | 视角逐步接近正交，接棒时位置、半径、颜色一致 | 保留面积转移、局部形变、接触停顿及 Safari 分层绘制，不做实时流体求解 |
| 分裂与环绕 | 同一个共同体再次显露个体 | 沿用既有运动节奏，不再多加一轮爆炸 | 保留分裂、断颈、交接和环绕；只设计进入、退出接口 |
| 重构与半周年 | 环绕末端回到开头的结构与角度，带着已看见的成员意义 | 一次重构即可；模型退至影片之外 | 保留半周年标题、视频、播放控制及结尾资料；调整标题/重构时序，避免双重高潮 |

连续性的关键不是“上一屏淡出、下一屏淡入”，而是可追踪的接棒：同一结构件留在画面内、运动方向连续、场景中心一致、前后状态可逆。大幅镜头运动只留给进入世界、揭示内部、最终重构三个转折；章节内部给足阅读停顿。不能强制读者等待动画才能访问正文。

避免“模型 + HTML 卡片”的检查方法：临时隐藏 Core 后，是否失去一条有意义的因果关系？如果只是画面少了装饰，就必须重设计。反过来，隐藏姓名与贡献后如果体验仍几乎不变，也说明人物尚未真正进入叙事。

## 保留与重新设计的边界

必须保留的资产：五境图像和文案、管理层资料、95 人名单、半周年影片、标徽候选与图标、现有纸白/深蓝黑/生态色体系、可回看体验、触屏原生横滑、reduced-motion 和基础内容回退。

优先复用的动画逻辑：`motion.js` 的可逆成员轨迹与周年粒子、`liquid.js` 的汇聚/分裂与面积守恒、`touch-timeline.js` 的有界事件补帧、手机的 SVG 母滴/连接/子滴分层、离屏休眠和生命周期处理。原有文字入场与管理层横向浏览继续使用。

需要重新设计：Core 本体、首屏字标与 Core 的身份分工、第一段地貌进入、五境接缝、bridge-orb 替换、结构到节点及液滴的交接、片尾重构。Hero 原有地貌绘制可以沿用，但不得在移动端无预算地同时运行波浪双 Canvas 和满屏 WebGL。

## 技术决策与主要风险

保留静态站点与现有发布方式；实验不引入 React/Nuxt，也不需要后端。建议使用锁定版本、随实验本地交付的 Three.js，避免运行时依赖外部 CDN。第一版一个 renderer、一个 camera rig、一个持久 Core 根节点、一个场景；章节只是状态配置。持续场景不意味着所有纹理与对象必须同时驻留。

最重要的架构边界是**一个滚动事实来源、一个帧调度者**。桌面适配既有 `renderedScroll` 和章节局部进度，触屏适配 `TwoNMobileStory.latest/phase()`；Core 不能自己安装 wheel/touchmove 劫持或再加 Lenis。现有对象在 IIFE 内，不是即插即用插件，后续只在实验副本中开放小的状态接口。

| 风险 | 为什么是当前项目的实际风险 | 最先验证 |
| --- | --- | --- |
| 原生横滑与 WebGL 不同步 | touch 路径由浏览器合成线程滚动，固定 Canvas 在 rAF 更新；细连接容易漂移 | 原生快速正反横滑，不先用 3D 细线贴合移动文字 |
| 双重渲染与合成压力 | Hero 已有两个 2D Canvas、图集与波浪；叠加大面积透明 3D 会增加填充负担 | 第一段并行开销与帧时间；轻档冻结远景或降低重绘，保留空间运动 |
| 液滴交接跳变 | 原系统是二维面积守恒，新模型是三维体积；不是同一物理系统 | 靠近正交的投影交接；比较屏幕面积，不声称真实三维液体守恒 |
| 持续内存占用 | 五张图原始解码约 30 MiB，另有图集、Canvas、GPU 纹理与视频 | 纹理邻接预取、释放和多次回看；影片仍按需加载 |
| 品牌与文字失焦 | 小屏模型会直接挤压姓名与贡献 | 手机独立构图，内容区域禁止主体覆盖 |
| 生命周期与错误恢复 | 现有代码有 hidden/pageshow/resize；WebGL 另有 context lost | 后台返回、旋转、BFCache、上下文丢失与恢复 |

Lusion 的 Canvas 随原生滚动移动并补偿位置可作为后备方案，但其 overscan 会增加像素量，不能未经测量直接套入横滑站点。首选降低精细 DOM 锚定需求，使用宽容的空间接棒；若仍不可接受，再做两种挂载方案的窄范围比较。

## 阶段路线与退出条件

| 阶段 | 类型与独立成果 | 通过条件 | 不通过时 |
| --- | --- | --- | --- |
| 0 · 判断方向 | 研究；基线快照、参考证据、叙事图谱、预算与镜头定义 | 有明确品牌理由、可复用资产、兼容路径与最小证伪范围 | 若只是展示技术则停止；当前允许进入 1，参考现场体验仍有待核实项 |
| 1 · 最小叙事 | 原型；Hero → 花园 → 沙漠 → 海洋 → 首次展开，以及同范围 v1 对照 | 识别、空间关系、可逆滚动、桌面稳定、iPhone 可接受、首屏预算全部通过，详见 PROTOTYPE.md | 聚焦最多两轮主要修正；仍不优于 v1 则保留为研究，不铺满五境 |
| 2 · 最难交接 | 局部 prototype；一个管理层阅读段 + Core 节点 → 现有液滴 → 分裂环绕 → 重构 | 姓名和贡献完整，全部液滴阶段保留，正反滑无断层；同屏只保留必要重绘 | 无法保住液滴质量或内存持续增长，则退回局部 3D；不进入全站 |
| 3 · 全篇整合 | 正式开发候选，仅在实验分支；补齐五境、所有人物、影片与首尾闭环 | 全部内容一致；桌面/手机分级都能理解同一故事；深链接、键盘、低动态、回退可用 | 修复受影响边界，不以删除成员、缩减动画阶段换取通过 |
| 4 · v2 决策 | 对照审查、真机记录、资源与维护说明、可独立回滚的候选版本 | 故事与辨识度明显增益，性能和可用性均通过，维护成本可承受 | 保留 v1 正式站；可继续作为独立实验，不强行发 v2 |

每阶段提交一个可恢复检查点：成果、验证结果、未通过事项、下一步。研究、原型、全站整合分别留提交，不累积到最后才保存。缺少真机证据标为“待验证”，不是默认通过；云端桌面截图不能代替手机 GPU 验收。

## 当前结论

可以继续阶段 1。现在不能宣称第一阶段视觉或性能合格，更不能进入阶段 3。下一段具体工作已经定义，不需要用户提前选择引擎、镜头或任务拆分：先对比 Core 两种剪影，选定后做限定范围原型，优先打通真实滚动、前景遮挡、失败回退和测量。

完整方案能否在 iOS Safari 承受，目前没有实测答案。单个低复杂度 Core 有合理可行路径，但五境纹理、旧 Hero 绘制、液滴与视频同时常驻/运行的方案不应采用。能持续保留的是“同一个世界”的感觉，而不是所有特效同时开启。
